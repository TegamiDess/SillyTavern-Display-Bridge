# Share a configured card

Display Bridge **0.17.0** and V3 Asset Sprites **0.8.0** can export a configured card as one CCV3 CHARX file. Both extensions are needed to reproduce their display behavior on the receiving SillyTavern installation.

## Quick steps

1. Import and configure your card normally. If you edited the UI profile, use **Review preset for this character → Apply imported UI profile** first. An unapplied editor draft is not exported.
2. Select the card. Open the extensions menu beside the chat input and choose **Export configured card (CHARX)**.
3. Review the image/rule/profile counts and any missing-asset notices. Confirm to download the file. Export does not replace your original card or archive.
4. Share that `.charx`. The recipient uses **Import card with images and supported UI**, then reviews SillyTavern's character-regex permission as usual. A separate UI-profile import is unnecessary.

Use this extension's import command for the full handoff. Native SillyTavern import and ordinary drag-and-drop do not supply the portable-rule rebuilding step. The portable-rule payload requires V3 Asset Sprites 0.7.0 or newer; old versions do not understand it.

## Included

- Saved card description, prompts, greetings, lorebook embedded in the card, author/creator notes, tags and other standard CCV3 fields.
- The **applied** UI profile: configured panels, mappings, outfit categories, declared default appearance, theme and supported behavior.
- All declared supported images and mapped extra images, including alternatives that are not currently visible. References use logical asset names, and the archive contains their bytes. Shared files are bundled once.
- Current avatar artwork, re-encoded to avoid embedding an old character-metadata payload inside the avatar image.
- Verified generated image-rule definitions and their disabled states. Import rebuilds installation-specific markers and bindings. Unrelated character regex rules remain ordinary card metadata.

Current chat outfit/visibility choices are not the profile's default choices. Set the desired default in the profile before exporting. An image-only configured export explicitly suppresses UI rediscovery from retained source scripts.

## Importing the same archive into Risu

From V3 Asset Sprites 0.7.1, ordinary named images use `type: "x-risu-asset"`. [Risu's importer](https://github.com/kwaroran/RisuAI/blob/main/src/ts/characterCards.ts) places these in its asset library; generic `image` entries instead go into its separate card-assets collection. The main avatar remains `icon`, and explicit roles such as `emotion`, `background` and other custom types are preserved. Exact logical names and file bytes are unchanged. This extension accepts the same type on SillyTavern import, so no second copy of the images is needed.

To correct an older configured export, select its imported card in SillyTavern and export it again with the updated provider. An already imported Risu card is not changed automatically.

This fixes asset classification, not full UI portability. Risu uses retained Risu scripts; it does not run a Display Bridge profile or our portable SillyTavern image-rule payload. A card built only with a Display Bridge profile will not acquire the same panels in Risu. Original scripts, assets or archive attachments omitted earlier cannot be reconstructed by changing the asset type.

## Not included / limits

- Chats, API settings, extension-global settings, recovery backups, importer history, local asset paths generated by these extensions, saved per-chat display choices and regex permission approvals.
- Separately linked SillyTavern lorebooks that are not embedded in the card. Export warns when a link exists without an embedded book.
- Unavailable images/audio and unsupported assets (video/models/fonts or unrecognized audio formats), alternate avatars or original archive-only attachments. A missing/unsupported asset is listed before download. You may cancel or explicitly accept an `-incomplete.charx`; its metadata and included notes retain the omissions. No remote asset downloads are performed by export.
- General Lua/STscript or story-variable conversion. Preserving source scripts as card metadata does not make their behavior work in SillyTavern.

This rebuilds a configured distribution card; it is not a lossless copy of the original archive. Keep the original. Card-authored text and third-party extension metadata are preserved and may themselves contain private information or links; this export is not an anonymizer.

Export runs on demand, with sequential local reads and a 256 MB image-byte limit (up to 10,000 distinct logical names, each at most 256 characters). It adds no background observers or polling. Packaging a large gallery temporarily uses memory and may take time. Modified or unverified generated regex rules block export instead of silently replacing your edits: review the rule and use the existing resync/recovery flow first.

## Portable format and QA

The archive follows the [CCV3 specification](https://github.com/kwaroran/character-card-spec-v3/blob/main/SPEC_V3.md): root `card.json`, `chara_card_v3` / `3.0`, `embeded://` asset URIs and ASCII archive filenames. The UI definition occupies `data.extensions.display_bridge_profile`.

`data.extensions.v3_asset_sprites` contains `{version:1, ui:"profile"|"none", rules:[...]}` and optional `incomplete` notices. Each rule has `id`, `name`, `source`, `flags`, `output`, and `disabled`. Only the existing reviewed image-template grammar is accepted. It contains no runtime markers, approval signatures or trust grants. Unknown versions, duplicate/unsupported IDs and invalid templates are rejected before native import. Existing disabled choices win when resyncing a previously configured character.

The browser acceptance matrix exercises asset-only, Afternoon, Community, Witchcure, streamer and assembled-scene export → fresh import → re-export. It checks profiles/defaults, asset bytes, fresh markers, disabled rules, no duplicate rules on rescan, permissions and rendered panels. Failure tests cover missing assets, malformed rules, edited rules and cancellation. See [TESTING.md](TESTING.md) for the latest results and native-test limitations.

From 0.17.0 / 0.8.0, configured exports also include supported local MP3/WAV/Ogg tracks, with original logical names, in `assets/other/audio/`. The same ownership, collision and recovery rules apply. Playback state and live chat snapshots are not exported. See [scene controls](display-bridge/SCENE-CONTROLS.md).
